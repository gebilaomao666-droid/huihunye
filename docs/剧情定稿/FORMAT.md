# 剧情定稿 · Markdown 格式约定

本目录下除 `FORMAT.md` 外的所有 `.md` 文件，都按本约定书写，可以直接被 `_work/story/check_story.mjs` 解析。
文件按章节拆开（`01_……md` 到 `10_……md`），`00_附录.md` 放道具表、短信、墓志铭和提示系统。

## 1. 层级

| 写法 | 含义 |
|---|---|
| `# 第一章：……` | 章标题，只给人看，脚本忽略 |
| `## node_id` | 一个剧情节点开始。id 只用字母、数字、下划线 |
| `## @item code` | 道具定义（只在附录） |
| `## @sms node_id` | 进入该节点时推送的短信（只在附录） |
| `## @epitaphs` / `## @hint_system` | 墓志铭列表 / 提示系统说明（只在附录） |
| `### 选项` | 节点的选项列表 |
| `### 热点 hs_id ｜ 标签` | 探索场景里的一个热点 |
| `### 谜题 pz_id` | 一个谜题定义 |
| `### 条件段 flag` / `### 条件段 !flag` | 有（或没有）某旗标时，接在正文后面多显示的一段 |

## 2. 节点字段（`## node_id` 之后、第一个 `###` 之前）

每行 `- 键: 值`。没有的字段不写。

| 键 | 说明 |
|---|---|
| 章节 | 如 `第一章：末班车与夜路` |
| 场景 | 场景名 |
| 时间 | 状态栏时间 `HH:MM`；写 `—` 表示沿用上一个节点的时间（用于可以来回走的地下岔口） |
| 类型 | `普通` / `探索` / `谜题` / `死亡` / `结局` |
| 回到 | 探索场景关闭时回到的节点（returnNode） |
| 场景提示 | 探索场景顶部的一句操作提示 |
| 设旗标 | 进入节点即设置，逗号分隔 |
| 获得道具 / 消耗道具 | 进入节点即获得 / 消耗，逗号分隔 |
| 死亡名 / 死亡说明 | 死亡节点必填 |
| 结局代号 / 结局名 | 结局节点必填。同一代号可以有多个节点（G 有两个收尾） |
| 原文 | 底牌校验，可写多行：`照抄 node12`（与 nodes.js 原文逐字一致）、`照抄去首段 node08`（去掉原文第一段后逐字一致）、`照抄段落 node01 3`（正文中含原文第 3 段）、`v2成品稿 4.3`（与 v2 方案 §4 对应引用块一致，引号全半角视为相同）、`v2成品稿开头 4.2b`（正文以该块开头） |

正文写在 `正文:` 一行之后，用引用块。段与段之间用一个空的 `>` 行隔开：

```
正文:
> 第一段。
>
> 第二段。
```

## 3. 选项

`### 选项` 下每行一个：

```
- 选项文本 -> 目标id | 键: 值 | 键: 值
```

| 键 | 说明 |
|---|---|
| requireItem | 持有该道具才显示 |
| requireFlag | 有该旗标才显示 |
| requireFlags + 否则 | **判定选项**：选项总是显示；旗标（逗号分隔，全部满足）齐了去目标 id，不齐去 `否则` 指定的 id |
| setFlags | 选中时设置旗标 |
| 获得道具 | 选中时获得道具 |

## 4. 热点（探索场景）

```
### 热点 hs_id ｜ 标签
- 一次性: 是
- 显示条件: flagA, flagB      （全部满足才出现）
- 隐藏条件: flagC             （有此旗标就隐藏）
- requireItem: code          （需在背包选中该道具再点）
- requireFlag: flag
- 未满足提示: ……              （条件不满足时的提示文字）
- 未满足跳转: node_id          （条件不满足时直接跳走，如空手对视纸人）
- 消耗道具 / 获得道具 / 设旗标
- 谜题: pz_id                 （点它进入同节点下定义的谜题）
- 跳转: node_id               （点完离开场景）
- 死亡: node_id               （点了就死）
- 提示条: ……                  （toast）
- 特写标题: ……
特写:
> 特写正文（同样用引用块）
```

"一次性"的热点被点过后视为已用（脚本里记为内部旗标 `used:hs_id`）。

## 5. 谜题

```
### 谜题 pz_id
- 类型: ……
- 位置: node_id 或 node_id#hs_id
- 答案: ……
- 线索: 引用1, 引用2           （给人看：线索出现在哪）
- 必经线索: 引用A, 引用B       （脚本校验：进入谜题前，必须至少见过其中一个；可写多行，每行一组）
- 成功设旗标 / 成功获得
- 成功跳转: node_id
- 成功文本: ……
- 失败后果: ……
- 失败跳转: node_id
- 提示1: ……  （烧一张黄纸：爷爷一句俗话，指方向）
- 提示2: ……  （烧两张：纸条浮字，给线索）
- 提示3: ……  （烧三张：四指血手印按在答案上）
```

线索引用写 `node_id`（进入过该节点即算见过）或 `node_id#hs_id`（点过该热点才算见过）。

## 6. 道具（附录）

```
## @item code
- 名称: ……
- 描述: ……
- 组合: other_code -> result_code | setFlags: flag | 提示: ……
```

组合时两个原料都消耗，产物加入背包；产物和某个原料同名时，该原料保留（用于"把碎片拼进遗照"）。

## 7. 自查脚本

`node _work/story/check_story.mjs` 会：解析全部文件；检查选项、热点、谜题指向的 id 都存在；从 `node01` 出发做带旗标/道具的状态搜索，给出每个结局、死亡是否可达以及最短路径节点数；检查每个旗标有设有读、每件道具有拿有用；校验必经线索在谜题之前出现；对照 `nodes.js` 和 v2 方案校验底牌与成品稿；统计字数并扫描文风禁用词。
